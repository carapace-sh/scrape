# scrape - Agent Guide

Command scrapers that generate carapace-bin completion specs by patching and building upstream CLI tools.

> **Requirement**: The [carapace](https://github.com/carapace-sh/carapace-bin/blob/master/skills/carapace/SKILL.md) skill **must** be loaded before working here — specifically its `references/scrape.md` reference, which covers supported frameworks, the patch-and-container pattern, and how scraping works. Load the skill via its SKILL.md, then read `references/scrape.md`.

## Overview

Each scraper clones a CLI tool at a pinned version, applies a patch that injects a carapace spec generator, builds it, and runs it so the spec is printed to stdout. The workflow captures stdout into a YAML file under `gh-pages/{command}/{version}.yaml`.

Scrapers are framework-aware: the patch and build steps depend on the CLI's framework (cobra, urfave/cli, kingpin, kong, clap, or Python argparse).

## Commands

```bash
./init.sh                          # Regenerate compose.yaml and .github/workflows/scrape.yml from package.json
docker compose build SERVICE      # Build image for a scraper
docker compose run SERVICE         # Run a specific scraper locally (prints spec to stdout)
docker compose run --quiet SERVICE > command.yaml  # Capture the spec
```

Run `./init.sh` after any change to `package.json` — it regenerates both `compose.yaml` and `.github/workflows/scrape.yml`, both of which are gitignored.

## Project Structure

- `package.json` - Maps commands to GitHub repos and versions (`"command": "https://github.com/org/repo#version"`). Dependabot keeps these current.
- `scrapers/{command}/Dockerfile` - Builds the CLI with carapace patches injected
- `scrapers/{command}/{command}.patch` - Git patch that injects carapace spec generation
- `scrapers/{command}/` - May contain additional helper scripts (e.g. `openstack/scrape.py`)
- `init.sh` - Generates `compose.yaml` and `.github/workflows/scrape.yml` from `package.json`
- `compose.yaml` - Generated by `init.sh` (gitignored) — one service per command
- `.github/workflows/scrape.yml` - Generated by `init.sh` (gitignored) — one job per command, each calling the template
- `.github/workflows/scrape-template.yml` - Reusable workflow: checks out `gh-pages`, runs `scrape.sh`, uploads artifact, pushes on master
- `.github/workflows/scrape.sh` - Builds and runs a single scraper; writes output to `gh-pages/{command}/{version}.yaml` if missing
- `.github/workflows/dependabot.yml` - Auto-approves and merges Dependabot PRs

## Supported Frameworks and Base Images

| Framework | Language | Base image | Spec invocation |
|-----------|---------|------------|-----------------|
| **cobra** | Go | `golang` | `carapace.Gen(cmd)` via patch; entrypoint `cmd _carapace spec` |
| **urfave/cli v2** | Go | `golang` | `spec.Register(app)`; entrypoint `cmd _carapace spec` |
| **kingpin v2** | Go | `golang` | `spec.Register(app)`; entrypoint `cmd _carapace spec` |
| **kong** | Go | `golang` | Register hidden `_carapace spec` subcommand |
| **clap** | Rust | `rust` | `carapace_spec_clap` crate; build runs binary which emits spec |
| **argparse** | Python | `python:3.12-slim` (multi-stage with `golang` for the converter) | `carapace-spec-argparse` converts JSON dump of the argparse tree to YAML |

See `references/scrape.md` in the carapace skill for framework-specific patch examples.

## CI/Automation

- Dependabot updates `package.json` versions daily; `dependabot.yml` auto-approves and merges those PRs.
- On push/PR to master, `scrape.yml` runs one job per command via `scrape-template.yml`.
- Each job checks out `gh-pages`, runs `scrape.sh <command>`, which:
  - Builds the Docker image
  - Runs the container and captures stdout
  - Writes `gh-pages/{command}/{version}.yaml` if it does not already exist
  - Uploads the artifact
- On master, new specs are committed and pushed to the `gh-pages` branch.
- If the output file already exists, the scraper skips silently.

## Adding a New Scraper

1. Add an entry to `package.json`: `"command": "https://github.com/org/repo#version"`.
2. Run `./init.sh` to regenerate `compose.yaml` and `scrape.yml`.
3. Create `scrapers/{command}/Dockerfile`:
   - Pick the base image matching the language (`golang`, `rust`, `python:3.12-slim`).
   - Clone the repo at `VERSION`, apply the patch, install dependencies, build.
   - Set `ENTRYPOINT` to invoke the spec generator so the spec goes to stdout.
4. Create `scrapers/{command}/{command}.patch` that injects the carapace spec generator:
   - **cobra**: add `github.com/carapace-sh/carapace` import and `carapace.Gen(cmd)` call.
   - **clap**: add `carapace_spec_clap` dependency and wire the `Generator` trait.
   - **argparse**: dump the argparse tree to JSON and convert with `carapace-spec-argparse`.
5. Build and run locally to verify: `docker compose build command && docker compose run --quiet command > /tmp/command.yaml`.

## Gotchas

- `compose.yaml`, `scrape.yml`, and `gh-pages/` are gitignored — run `./init.sh` after modifying `package.json`.
- Each scraper dir must contain exactly one `.patch` file matching the directory name (e.g. `scrapers/docker/docker.patch`). Additional helper files (like `scrapers/openstack/scrape.py`) are allowed when the framework needs them.
- The patch filename must match the directory name because `Dockerfile`s reference it as `ADD <command>.patch /`.
- `scrape.sh` replaces `/` in versions with `_` for the output filename (e.g. branch names like `release/0.22.0` become `release_0.22.0`).
- Go-based cobra scrapers often need `go mod tidy` and `go mod vendor` after adding the carapace dependency; some repos use `vendor.mod`/`vendor.sum` (e.g. docker) and need those copied to `go.mod`/`go.sum` first.
- Rust clap scrapers use `cargo add carapace_spec_clap` (and sometimes `clap_complete`) before `cargo install`.
- The `gh-pages` branch is the source of truth for generated specs — check whether a version's spec already exists there before re-scraping.
